# LeetCode Prep — Three Phases

| Phase | Target | Length | Volume | Start here |
|---|---|---|---|---|
| **[Phase 1](Phase1/README.md)** | SDE II — well-rounded coverage | 13 weeks | 215 problems | [schedule](Phase1/schedule.md) |
| **[Phase 2](Phase2/README.md)** | SDE III — depth, Hards, build-it-yourself | 16 weeks | 207 problems + 11 exercises | [schedule](Phase2/schedule.md) |
| **[Phase 3](Phase3/README.md)** | Above the bar — not interview prep | open-ended | menu, not a schedule | [catalogue](Phase3/catalogue.md) |

**Phase 1 + Phase 2 = 29 weeks (~7 months) at 1.5h/day**, and together they cover all 432 distinct
problems in [Reference/](Reference/) except three deliberately promoted to Phase 3.

[Reference/](Reference/) is the source material — 19 topic files with the full problem tables,
Java notes, pattern-recognition tables and coverage audits. The phases *select and schedule* from
it; they don't replace it. Keep marking **Hint?** in the Reference tables, since that column is
what every revision day reads.

## The split

| | Phase 1 | Phase 2 |
|---|---|---|
| Hard density | ~8% | ~45% |
| Problems per session | ~3.4 | ~2.6 |
| Graphs + DP share | 27% of problems | 35% of days |
| From-scratch exercises | 0 | 11 |
| What it buys | pattern recognition | depth, justification, and building things live |

Phase 1 teaches you to *recognize*. Phase 2 teaches you to *justify* — which is the actual
difference between the two levels, and the reason Phase 2 is four weeks longer for fewer problems.

## Rules that apply to all phases

1. State the approach and complexity before typing. For DP, finish *"`dp[i][j]` = …"* out loud.
2. Re-derive, don't recall.
3. Time-box: 30 minutes in Phase 1, 45 in Phase 2. Then read, re-implement unaided, mark Hint?, move on.
4. Write compilable Java. Dry-run unprompted. Find your own bugs.
5. Never trade a revision day for a problem day.
